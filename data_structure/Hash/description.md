## 哈希

目标：顺序查找的复杂度为`O(n)`,平衡树为`O(log n)`,希望实现`O(1)`的查找和插入，通过某种函数使得需要元素的存储位置和键值有映射关系（哈希函数）

哈希函数：

* 期望哈希值的范围尽可能随机分布，以减小哈希冲突
* 期望哈希值依赖于键中的所有值及其位置
* 不希望在选择键时系统的非随机模式导致冲突

哈希函数举例（对整数）：模运算，`a mod tableSize (哈希值范围：0,1,...,tableSize-1)`：满射但不单射，容易导致哈希冲突，表大小需要谨慎选择，（素数）

（对字符串）：对字符串`c0c1c2c3...cn-1`，可以采用`(c0+c1+c2+...+cn-1) mod size`，每个字符对应各自的`ASCII`值（也容易导致哈希冲突）优化`e.g.`

    ```C++
    for(auto&i:string){
        hash=(i+hash*29)%tableSize;
    }
    ```

负载系数：假设有n个元素需要被存储，负载系数`λ=n/tableSize`,好的哈希函数希望负载系数小于1但尽可能接近1，当系数大于1时可选择链表

哈希冲突：两个或多个元素映射到同一个哈希值

解决方法：1.单链表，同一个哈希值处设置单链表，同一哈希值的多个元素进入链表，最大`O(n)`的查找复杂度，平均查找`O(1)+O(λ)`浪费空间，但实现简单

2.寻找空位置进行元素映射

* 线性探测：当发生冲突时，`h(x)=(hash(x)+c*i) mod tableSize`,其中c为常数，i从0，1，，一直到找到空位置为止，期望在回到主位置之前能谈测完所有可能的空位置，因此常数c的理想选择是小于且与`tableSize`互质的数，此外还可以准备一个探测数序列`perm[n]`，则`h(x)=(hash(x)+perm[i]) mod tableSize`，问题：原本映射到不同位置的元素会探测相同的备选位置,，，，，可以更好地利用空间，表稀疏的时候速度很快
* 平方探测：`h(x)=(hash(x)+c1*i^2+c2*i+c3) mod tableSize`,可以减缓线性探测的问题，但是映射到相同位置的元素的备选位置仍然一样
* 双哈希：`h(x)=hash1(x)+i*hash2(x)`，空间友好，快速，但是哈希函数需要小心设计

重哈希：`λ`超过特定值的时候，构建一个更大的哈希表，大小约为原来的两倍

* 新表有新的哈希函数，所有元素的哈希值需要重新计算，放在表中新位置，复杂度`O(n)`
